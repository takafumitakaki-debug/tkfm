# TKFM Share ― 招待した人だけの写真・動画共有

iPhone の容量を気にせず、家族・友人など**招待した人だけ**で写真・動画を共有するアプリ。
写真・動画の本体は自分で用意したサーバー（自宅PC・NAS・VPS など）に保存し、iPhone には残さない。

- App Store 不要。Safari で開いて「ホーム画面に追加」すればアプリのように使える
- 外部サービスにデータを預けない（Google・Apple・LINE のアルバムに依存しない）
- サーバー側は Node.js だけで動く（npm install 不要）

## iPhone の容量を使わない仕組み

| 場面 | iPhone 側で起きること |
|---|---|
| アップロード | 写真アプリから選ぶ → 8MB ずつサーバーへ送信。完了すると「iPhoneの写真アプリから削除しても大丈夫」と表示される |
| 一覧 | 端末で作った小さなサムネイル（長辺480px）だけを読む |
| 写真を見る | 軽いプレビュー（長辺2048px）を表示。元画像は「元の画質で表示」を押した時だけ |
| 動画を見る | サーバーからストリーミング再生（シーク可能）。ダウンロードはしない |
| 手元に戻したい | 「保存」→ 共有シートの「画像を保存／ビデオを保存」で写真アプリに戻せる |

キャッシュはブラウザの一時領域だけで、iOS が必要に応じて自動で消す。

## 「指定された人だけ」の仕組み

- アカウント登録画面は**ない**。管理者が「メンバー → 招待リンクを作成」で本人専用のリンクを発行し、LINE などで送る
- 招待リンクは **1回だけ・7日間**有効。開いた端末にだけログイン状態が保存される（Cookie、約1年）
- 2台目の端末（iPad・PC・ホーム画面アプリ）は、ログイン済み端末の「設定 → この端末以外でログイン」で出る **8桁コード（10分間有効）** で追加
- 管理者は、メンバーの利用停止（全端末から即ログアウト）、機種変更時の再ログインリンク（24時間）の発行ができる
- 写真・動画の URL を知っていても、ログインしていなければ見られない

> iPhone では Safari と「ホーム画面に追加」したアプリでログイン状態が別々になる。
> 招待リンクを Safari で開いて参加 → ホーム画面に追加 → ホーム画面のアプリで 8桁コードを入力、の順で使う（アプリ内の案内にも表示される）。

## できること

| 分類 | 機能 |
|---|---|
| アルバム | 作成・名前変更・削除（作った人か管理者）、表紙・件数・更新日の表示 |
| 追加 | 写真・動画の複数選択、2件同時送信、途切れても自動再試行（同じ位置から再開）、同じファイルの二重登録を自動スキップ、送信中は画面スリープを抑止 |
| 表示 | 撮影日ごとにまとめた一覧（EXIF・動画の撮影日時を読み取り）、全画面ビューア（スワイプ・矢印キー）、動画再生 |
| 保存・削除 | 元ファイルの保存、削除（追加した人か管理者） |
| メンバー | 招待・未使用リンクの取り消し・利用停止／再開・管理者の追加・名前変更 |
| その他 | 自分のログイン端末一覧と強制ログアウト、サーバー容量の表示、ダークモード |

## サーバーの起動

Node.js 22.13 以上が必要（標準の SQLite を使うため）。`ffmpeg` が入っていれば、PC から上げた動画のサムネイルもサーバー側で作る（無くても動く）。

```sh
cd photo-share
npm start
```

初回起動時、ターミナルに**管理者用の招待リンク**が表示されるので、自分の iPhone で開く。
リンクを無くしたときは `npm run invite -- 名前` で管理者リンクを再発行できる。

### 設定（環境変数）

| 変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `8080` | 待ち受けポート |
| `DATA_DIR` | `./data` | 写真・動画とデータベースの保存先。**容量の大きいディスクを指定する** |
| `PUBLIC_URL` | （なし） | 外から見たときの URL（例 `https://photos.example.com`）。招待リンクに使われる |
| `TRUST_PROXY` | （なし） | リバースプロキシ・Cloudflare Tunnel の後ろで動かすときは `1` |
| `MAX_UPLOAD_GB` | `20` | 1ファイルの上限 |
| `APP_NAME` | `TKFM Share` | 画面に出るアプリ名 |
| `FFMPEG` | `ffmpeg` | ffmpeg のパス。`off` で無効 |

### 外（iPhone のモバイル回線）から使えるようにする

HTTPS が必須（ログイン Cookie を安全に扱うため）。例：

- **Cloudflare Tunnel**：自宅の PC・NAS でもポート開放なしで `https://` の URL が持てる。`PUBLIC_URL=https://… TRUST_PROXY=1 npm start`
  - 無料プランはアップロード1リクエスト100MBまでだが、このアプリは8MBずつ送るので大きな動画も問題ない
- **VPS + Caddy**：`reverse_proxy localhost:8080` だけで HTTPS 化される。ストレージの大きいプラン or オブジェクトストレージのマウントを選ぶ

### バックアップ

`DATA_DIR` を丸ごとコピーすれば全データ（`tkfm-share.db` と `media/`）を保存できる。
iPhone から消した写真はここにしか無くなるので、**外付けディスクやクラウドへの定期バックアップを必ず設定する**。

## 開発

```sh
npm test   # API の結合テスト（招待・アップロード・Range 配信・権限・ログインコード・利用停止）
```

| ファイル | 内容 |
|---|---|
| `server.js` | 起動・管理者招待の発行 |
| `lib/app.js` | HTTP サーバー、API、認証、アップロード受信、動画の Range 配信 |
| `lib/db.js` | SQLite のスキーマ |
| `public/app.js` | 画面（アルバム・ビューア・アップロード・設定・メンバー管理） |
| `public/meta.js` | 撮影日時の読み取り（JPEG の EXIF／MP4・MOV） |

## 注意・制限

- iPhone の写真選択画面は、HEIC 写真を自動で JPEG に変換して渡すことがある（画質はほぼ同等）。動画は「互換性優先」で圧縮される場合があるため、元のまま送りたいときは選択画面の「オプション」で「現在のフォーマット」を選ぶ
- iPhone で撮った HEVC（H.265）動画は、Windows の Chrome などでは再生できないことがある（「保存」からダウンロードすれば再生可）
- アップロード中に別のアプリへ切り替えると iOS が送信を止める。戻れば自動で続きから再開する
- 全メンバーが全アルバムを見られる（アルバム単位の公開範囲設定は未対応）
