# 比較ナビ

欲しいものを入力すると、複数のショップから**同じ比較項目**（本体価格・送料・ポイント・評価・レビュー数・在庫）を集め、
**同じ商品ごとにまとめて**ショップ間を比較し、重視ポイントに合わせておすすめ順に並べます。

## 使い方

```bash
cd hikaku-navi
npm start          # http://localhost:3000
npm test
```

依存パッケージなし（Node.js 18 以上）。APIキーを設定しない場合は**デモデータ（架空の商品）**で動きます。

## 実際のショップから収集する

| ソース | 環境変数 | 取得先 |
|---|---|---|
| 楽天市場 | `RAKUTEN_APP_ID`（任意で `RAKUTEN_ACCESS_KEY`, `RAKUTEN_AFFILIATE_ID`） | [Rakuten Developers](https://webservice.rakuten.co.jp/) |
| Yahoo!ショッピング | `YAHOO_APP_ID` | [Yahoo!デベロッパーネットワーク](https://e.developer.yahoo.co.jp/) |

```bash
RAKUTEN_APP_ID=xxxx YAHOO_APP_ID=yyyy npm start
```

キーが1つでもあればそのソースだけで動き、デモは使いません（`DEMO=1` で併用）。
エンドポイントが変わった場合は `RAKUTEN_ENDPOINT` / `YAHOO_ENDPOINT` で上書きできます。

> 収集は各社の公式検索APIを使います。HTMLを直接スクレイピングすることは、多くのECサイトで利用規約上禁止されているため行っていません。

## 仕組み

```
検索語 ─┬─ 楽天API ──┐
        ├─ Yahoo API ─┼─ 共通項目にそろえる (lib/offer.js)
        └─ (デモ) ────┘        │
                      同じ商品をまとめる (lib/group.js)
                       ① JANコード一致  ② 型番の一致/不一致  ③ 商品名の類似度
                               │
                      スコアリング・おすすめ理由 (lib/recommend.js)
                       実質価格 = 本体 + 送料 − ポイント
                       評価はレビュー件数で補正（ベイズ平均）
```

| 重視ポイント | 価格 | 評価 | レビュー数 | 取扱店数 |
|---|---|---|---|---|
| バランス | 40% | 35% | 15% | 10% |
| 安さ重視 | 70% | 15% | 10% | 5% |
| 評価重視 | 15% | 55% | 25% | 5% |

- 同じ検索語の結果は10分キャッシュし、APIへの負荷を抑えます
- 1つのソースが失敗しても、他のソースの結果で比較します（画面に失敗を表示）
- 検索条件はURLに残るので、結果ページをそのまま共有できます

## ソースを追加する

`sources/` に `{ id, label, enabled(), search(query) }` を返すモジュールを作り、`makeOffer()` で共通項目にそろえて返し、
`lib/crawl.js` の `activeSources()` に加えます。

## 既知の制約

- 楽天APIは送料「別」の場合の金額を返さないため、送料0円として計算し「別」と表示しています
- 商品名だけで同一判定するケース（JAN・型番なし）は、まれに別商品をまとめたり、同じ商品を分けたりします
