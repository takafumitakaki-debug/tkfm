# 比較ナビ

欲しいものを入力すると、複数のショップから**同じ比較項目**（本体価格・送料・ポイント・評価・レビュー数・在庫）を集め、
**同じ商品ごとにまとめて**ショップ間を比較し、重視ポイントに合わせておすすめ順に並べます。

## 使い方

```bash
cd hikaku-navi
npm install
npm start          # http://localhost:3000
npm test
```

Node.js 18 以上。初回は `npm install`（AI解釈用の `@anthropic-ai/sdk` のみ）。APIキーを設定しない場合は**デモデータ（架空の商品）**で動きます。

## 曖昧な語でも推測して検索

うろ覚え・表記ゆれ・誤記を含む入力でも、検索語を推測して順に試します（最大4回、十分な件数が集まったら止める）。

| 推測の段階 | 例：`モナルシーダネオ3 wide elite 27cm` |
|---|---|
| ① AI解釈（任意） | 正式名・メーカー・カテゴリ・検索語の候補を推測（例：ミズノ モナルシーダ NEO 3 WIDE ELITE） |
| ② 条件の切り出し | `27cm` は検索語から外し、**サイズ条件**として絞り込みに使う |
| ③ 表記ゆれ | `モナルシーダ ネオ 3 wide elite` / `… ワイド エリート` / `… neo iii …`、ひらがな→カタカナ、全角→半角 |
| ④ 緩和検索 | ヒットが少なければ語を減らす（`モナルシーダ ネオ 3` → `モナルシーダ ネオ` …） |

- 集めた商品は検索語との**関連度**を計算し、関連の薄いもの・条件（サイズ）が合わないものは除外、関連度の低いものは順位を下げます
- 画面に「もしかして：〇〇」「試した検索語」「除外した件数」を表示します

**AI解釈を有効にする**（任意）：`ANTHROPIC_API_KEY` を設定すると、Claude（`claude-opus-5-5`、`AI_MODEL` で変更可）が入力を解釈します。
カタカナ⇔英字のブランド名（モナルシーダ⇔MONARCIDA など）はルールでは推測できないため、AI解釈があると精度が大きく上がります。
未設定・失敗時はルールベースだけで動きます。

## 最新の情報に更新する

- 各結果に**最終取得時刻**を表示。「最新に更新」でキャッシュを使わず取り直します（APIでは `refresh=1`）
- 取得のたびに商品ごとの最安値を `data/store.json` に記録し、**前回比（▼¥800 など）・価格推移グラフ・記録中の最安値**を表示します
- **ウォッチ登録**した検索は、サーバーが `WATCH_INTERVAL_MIN`（既定60分）ごとに自動で取り直し、おすすめ1位が値下がりしたら履歴に残します
- 通常検索のキャッシュ時間は `CACHE_TTL_MIN`（既定10分）

| API | 内容 |
|---|---|
| `GET /api/search?q=&budget=&priority=&refresh=1` | 検索（refresh=1 で最新取得） |
| `GET /api/watch` / `POST /api/watch {q, priority, budget}` / `DELETE /api/watch?id=` | ウォッチ一覧・登録・解除 |
| `POST /api/watch/refresh` | ウォッチ中の検索をすべて今すぐ更新 |

## 実際のショップから収集する

| ソース | 環境変数 | 取得先 |
|---|---|---|
| 楽天市場 | `RAKUTEN_APP_ID`（任意で `RAKUTEN_ACCESS_KEY`, `RAKUTEN_AFFILIATE_ID`） | [Rakuten Developers](https://webservice.rakuten.co.jp/) |
| Yahoo!ショッピング | `YAHOO_APP_ID` | [Yahoo!デベロッパーネットワーク](https://e.developer.yahoo.co.jp/) |

```bash
RAKUTEN_APP_ID=xxxx YAHOO_APP_ID=yyyy npm start
```

キーが1つでもあればそのソースだけで動き、デモは使いません（`DEMO=1` で併用）。
エンドポイントが変わった場合は `RAKUTEN_ENDPOINT` / `YAHOO_ENDPOINT` で上書きできます。

> 収集は各社の公式検索APIを使います。HTMLを直接スクレイピングすることは、多くのECサイトで利用規約上禁止されているため行っていません。

## 仕組み

```
検索語 → 推測（AI解釈・条件切り出し・表記ゆれ・緩和） (lib/query.js, lib/ai.js)
  │
検索語 ─┬─ 楽天API ──┐
        ├─ Yahoo API ─┼─ 共通項目にそろえる (lib/offer.js)
        └─ (デモ) ────┘        │
                      同じ商品をまとめる (lib/group.js)
                       ① JANコード一致  ② 型番の一致/不一致  ③ 商品名の類似度
                               │
                      スコアリング・おすすめ理由 (lib/recommend.js)
                       実質価格 = 本体 + 送料 − ポイント
                       評価はレビュー件数で補正（ベイズ平均）、関連度で補正
                               │
                      価格履歴に記録・前回比 (lib/store.js)
```

| 重視ポイント | 価格 | 評価 | レビュー数 | 取扱店数 |
|---|---|---|---|---|
| バランス | 40% | 35% | 15% | 10% |
| 安さ重視 | 70% | 15% | 10% | 5% |
| 評価重視 | 15% | 55% | 25% | 5% |

- 同じ検索語の結果は10分キャッシュし、APIへの負荷を抑えます
- 1つのソースが失敗しても、他のソースの結果で比較します（画面に失敗を表示）
- 検索条件はURLに残るので、結果ページをそのまま共有できます

## ソースを追加する

`sources/` に `{ id, label, enabled(), search(query) }` を返すモジュールを作り、`makeOffer()` で共通項目にそろえて返し、
`lib/crawl.js` の `activeSources()` に加えます。

## 既知の制約

- 楽天APIは送料「別」の場合の金額を返さないため、送料0円として計算し「別」と表示しています
- 商品名だけで同一判定するケース（JAN・型番なし）は、まれに別商品をまとめたり、同じ商品を分けたりします
